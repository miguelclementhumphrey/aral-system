Overview

How the system works

The ARAL system has four layers of access. Each layer must be properly set up before the next one can operate. Nothing is accessible unless the layer above it has completed its setup — this is enforced by gates at every transition point.

Setup order

Super Admin → School Head → Teachers → Learners. No skipping. Each layer unlocks the next.

Authentication model

School IDs are issued by Super Admin, used once to activate, then replaced by a real password. The ID alone is never enough.

Roles

Role separation

RoleWhat they can doWhat they cannot do
Super Admin Register schools, issue School IDs, activate / suspend schools, reset passwords, view all schools Cannot create grade levels, add teachers, or touch learner data
School Head Complete school profile, create grade levels, add teachers to grade levels Cannot add learners, cannot access ARAL Dashboard directly
Teacher Complete own profile, add and profile learners, manage ARAL Dashboard for their grade level Cannot create grade levels, cannot see other teachers' data

Role separation must be enforced at the database/API level — not just by hiding buttons in the UI.

Super Admin

Layer 0 — Super Admin panel

The Super Admin is the system owner (e.g. DepEd IT division or your organization's administrator). This is a completely separate, secured panel — not accessible from the main school login screen.

ADMIN 01
Super Admin login
Separate URL, own credentials — never a School ID
  • Super Admin logs in using a dedicated username and strong password (not tied to any school).
  • This panel should be hosted on a separate route (e.g. /admin) and not linked from the public login page.
  • Enable two-factor authentication for the Super Admin account.
  • Failed login attempts lock the account after 5 tries and send an alert email.
ADMIN 02
Register a school
All school data is created here first

Required fields when registering a school:

  • School name (full official name)
  • School ID — system-generated automatically, or manually assigned. Must be unique. Never entered by the school themselves.
  • Division / District / Region
  • School Head name and contact (for delivery of the School ID credential)
  • Status: set to Pending by default
Validation Duplicate school names within the same division must trigger a warning. School IDs must be unique system-wide. No school is accessible until status is changed to Active.
ADMIN 03
Activate a school
This is the gate that allows the School Head to log in
  • Super Admin changes school status from Pending to Active.
  • The School ID is then delivered to the School Head through a secure channel: official email, SMS to the registered number, or a printed letter. Never posted publicly.
  • The system logs the date and method of delivery.
Result Once status is Active, the School Head can find their school in the login dropdown and use the issued School ID as a first-time credential.
ADMIN 04
Admin maintenance
Ongoing responsibilities
  • Suspend a school (blocks all logins for that school instantly).
  • Reset a School Head's password if they are locked out — generates a new temporary credential and delivers it securely.
  • View a list of all schools, their status, and last login activity.
  • Deactivate a school at the end of a school year if needed.
Authentication

Login system — two-layer model

The public login screen is shared by School Heads and Teachers. Authentication works differently for first-time vs. returning users.

First-time login (School Head only)

LOGIN 01
First-time School Head activation
School ID used once, then replaced
  • School Head selects their school name from the dropdown.
  • Enters the School ID issued by the Super Admin.
  • System checks: (1) school name exists, (2) school status is Active, (3) School ID matches.
  • If all pass and this is the first login → force a Set Your Password screen before anything else.
  • Password requirements: minimum 8 characters, at least one number, at least one special character.
  • After setting the password, the School ID is no longer accepted as a login credential — only the new password works from this point.
Gate The School ID becomes a reference/recovery code only. If the School Head forgets their password, the Super Admin resets it — they cannot simply use the School ID again.

Returning login (School Head)

LOGIN 02
Returning School Head login
School name + password only
  • School Head selects school name → enters password.
  • 5 failed attempts → account locked for 15 minutes, Super Admin notified.
  • On success → redirect to home screen (two-button view).

Teacher login

LOGIN 03
Teacher login flow
Only available after School Head setup is complete
  • Teacher taps the Teachers button (only active if grade levels and teachers have been added).
  • Sees a list of teacher names registered by the School Head for their school.
  • Selects their name and enters their PIN or password (system-generated on first enrollment, changeable after first login).
  • If a teacher's account is not yet activated by the School Head: show message — "Your account has not been activated. Contact your School Head."

School Head

School Head flow

After login, the School Head sees the two-button home screen. They tap the School Head button and must complete three steps in order before the Teachers button is activated.

SH 01
School Head profile setup
Required gate — nothing else unlocks until complete

Required profile fields:

  • Full name (First, Middle, Last)
  • Designation / position
  • Contact number
  • Email address
  • School district and division
  • School year / academic year
Gate — enforced server-side On every session start, check if profile is complete. If not, redirect to profile form. The Create Grade Level feature, Add Teachers feature, and all School Head menus remain inaccessible until every required field is saved.
Error prevention Validate each field inline as the user types — do not wait until submit. If the School Head exits mid-profile, auto-save a draft so they do not start over. Show a completion percentage or checklist so they know what is still missing.
SH 02
Create grade levels
Unlocks after profile is 100% complete

Available grade levels: Kinder, Grades 1 through 12, Floating.

  • Each grade level can only be created once per school. Already-created options are shown as disabled in the UI.
  • Once a grade level has teachers or learners assigned, it cannot be deleted — only deactivated.
  • Show a running list of created grade levels with a teacher count on each.
  • Creating a grade level automatically generates an ARAL Dashboard for that grade level — no manual setup needed.
Gate At least one grade level must be created before the Add Teachers option appears.
SH 03
Add teachers
Unlocks after at least one grade level exists

Required fields when adding a teacher:

  • First Name, Middle Name, Last Name
  • Grade level assignment (must select from already-created levels)

On save, the system automatically creates a teacher account with a system-generated PIN. This PIN should be delivered to the teacher (printed or via SMS).

Error prevention Warn if a teacher with the same full name is added to the same grade level. Validate that a grade level is selected before saving. Confirm success: "Teacher [Name] added to [Grade Level]."
Result — Teachers button activates Once at least one teacher has been added to at least one grade level, the Teachers button on the home screen becomes active. Show this change immediately after saving.
Teacher

Teacher flow

Teachers access the system through the (now activated) Teachers button. Their flow is also gated — they cannot add learners until their own profile is complete.

TCH 01
Teacher profile gate
Must complete before Add Learners is available

Required teacher profile fields (define your complete list — example):

  • Age, sex, date of birth
  • Years of service
  • Highest educational attainment
  • Contact number
  • Specialization / subject area
Gate — enforced server-side on every session Re-check profile completeness on each login. The Add Learners button remains locked and visually grayed out with a tooltip: "Complete your profile to add learners."
TCH 02
Select grade level
Auto-populated from School Head setup
  • Only grade levels the teacher is assigned to are shown — not all school grade levels.
  • If assigned to multiple grade levels, show all and let the teacher pick one per session.
  • The selected grade level determines which learner list and ARAL Dashboard the teacher sees.
TCH 03
Add and profile learners
Available only after teacher profile is complete

Required fields for each learner:

  • Full name (First, Middle, Last)
  • Learner Reference Number (LRN) — must be unique within the school
  • Date of birth, sex
  • Guardian name and contact
  • Address
  • Additional profiling fields as defined by your system
Error prevention Validate LRN format and uniqueness on entry — show error immediately, not after submit. If a learner with the same name already exists in the same grade level, warn: "A learner with this name exists. Check LRN before continuing." Never allow saving an incomplete learner profile.
TCH 04
ARAL learner identification
Flags a learner and opens the ARAL Dashboard
  • The ARAL Learner button appears next to each learner's row only after their full profile is saved.
  • Clicking it shows a confirmation: "Mark [Name] as an ARAL learner? They will be added to the ARAL Dashboard."
  • On confirm: learner is flagged in the database and the teacher is redirected to the ARAL Dashboard for their grade level.
  • If a learner is already flagged as ARAL, the button changes to "View in ARAL Dashboard" — no duplicate flagging allowed.
ARAL Dashboard

ARAL Dashboard

Each grade level has its own ARAL Dashboard, automatically created when the grade level is created by the School Head. Teachers do not set these up manually.

ARAL 01
Dashboard overview
Lists all ARAL-flagged learners for this grade level

Each learner row shows:

  • Learner name
  • Date flagged as ARAL
  • Completion status of their additional profiling (violet-highlighted sections)
  • Last updated date
  • Update Data button
ARAL 02
Update Data — additional profiling
The violet-highlighted sections

For each field in the additional profiling section:

  • Define the field name, data type (text, number, date, dropdown), whether required or optional, and allowed values if it is a dropdown.
  • Show the last-updated date so teachers can see if data is stale.
  • Auto-save a draft if the teacher navigates away mid-update.
Error prevention Validate all fields before saving. Never allow partial saves that appear complete. Show a save confirmation: "[Learner name]'s data has been updated."
ARAL 03
Weekly attendance
One record per learner per week

Fields per week:

  • Week dates — auto-populated from the school calendar. Teachers do not manually enter dates.
  • Per day, per learner: Present / Absent / Late toggle.
Error prevention Future dates cannot be marked. Past weeks are locked after a defined submission window (e.g. 3 days after the week ends — define this in system settings). If a learner has 3 or more consecutive absences, show a warning flag on their row.
ARAL 04
Monthly reading level
One record per learner per month

Fields per month:

  • Month — auto-populated, current month pre-selected.
  • Reading level — dropdown with defined categories (e.g. Non-reader, Frustration, Instructional, Independent — define your own).
Error prevention Only one reading level entry per learner per month is allowed. If an entry already exists, display it in read-only mode with an Edit button. Require a reading level before the month's record can be submitted. Never allow a blank reading level to be saved.
General rules

System-wide rules for error prevention

RuleImplementation detail
All gates are server-side Never rely only on hiding or disabling buttons in the UI. Validate every gate on the server before saving or displaying data. A user who bypasses the UI should still be blocked.
Session always knows the school Every piece of data created must be tied to the school ID stored in the session. Never trust client-sent school IDs.
No orphaned data Grade level created but no teachers assigned → flag it. Teacher added but no grade level selected → block the save. Learner added but profile incomplete → block the save.
Clear feedback at every step Every action (save, create, activate, flag) must show a success or error message. A blank response after submitting a form is never acceptable.
Role separation is strict School Heads cannot add learners. Teachers cannot create grade levels. Super Admin cannot touch learner data. Enforce at the API level with role-based access control (RBAC).
Audit logging Log every significant action (account created, grade level created, teacher added, learner flagged as ARAL, data updated) with a timestamp and the user who performed it.
Locked buttons always explain why Never show a grayed-out button with no explanation. Always show a tooltip or message stating the exact requirement that has not been met yet.
Draft auto-save Any multi-field form (profile setup, learner profiling, ARAL update data) must auto-save a draft on navigation away. Require confirmation before discarding a draft.
